# 批量 OCR · 扫描件 → 可搜索 PDF + Word + TXT

配合 `../scanner-pwa` 用：手机上把纸拍成 PDF，电脑上一条命令把里面的字认出来。

```bash
python ocr.py 扫描件.pdf
```

产出三个文件（默认在输入同目录的 `ocr_out/`）：

| 文件 | 是什么 |
|---|---|
| `xxx_ocr.pdf` | 图片原样保留，上面盖一层**看不见的文字** → 能全文搜索、能选中复制、能高亮 |
| `xxx.docx` | 识别出的文字，按页分页、字号按原文大小还原（标题大、正文小），Word 里直接改 |
| `xxx.txt` | 同上，纯文本 |

## 为什么放电脑上做

“一次几十页”这个量级，手机浏览器跑 OCR 是折磨：一页 5～15 秒、发热、切后台还会被 iOS 掐掉，而且浏览器里能用的中文模型比这里弱一截。电脑上同一页 3～6 秒，几十页一次跑完，你干别的去。

## 安装

```bash
pip install rapidocr_onnxruntime pymupdf python-docx pillow
```

RapidOCR 自带中英文模型（约 15MB，随包下载），**不需要联网也能一直用**，不调任何云接口。

## 用法

```bash
python ocr.py test/sample.pdf                 # 单个文件
python ocr.py D:\扫描件\                       # 整个目录里的 PDF 和图片
python ocr.py a.pdf b.png c.jpg -o D:\结果     # 指定输出目录
python ocr.py D:\扫描件\ --no-docx             # 只要可搜索 PDF
python ocr.py D:\扫描件\ --dpi 300             # 原件没有内嵌图片时，用更高分辨率渲染
```

支持的输入：`.pdf .png .jpg .jpeg .bmp .tif .tiff .webp`。

## 实测

用 `python test/make-sample.py` 生成的一张中文合同测试页（1240×1754）：

- 识别 17 个文本块 / 16 行，关键字段全部命中：标题、人名、地址、金额 `4800`、合同号 `HT-2026-0312` 都认对了。
- 单页耗时 **约 5～6 秒**（含模型加载 0.5s，同一进程内批量时只加载一次）。
- 输出 PDF 用另一个阅读器打开，搜索「房屋租赁合同」能定位命中。

可以自己跑一遍验证：

```bash
python test/make-sample.py
python ocr.py test/sample.pdf -o test/out
```

## 原理

1. PDF 里如果嵌的是一整张图（扫描件的常态），就**直接取原图**做 OCR，不重新编码，不损失画质；取不到才按 dpi 渲染。
2. RapidOCR 出文字 + 每行的四点坐标。
3. 新建一页，把原图放回原位，再用 PDF 的「不可见文字」模式（`render_mode=3`）把每个词按坐标贴上去，字号按识别框高度换算、宽度再做一次缩放贴合 —— 这样选中文字时高亮框正好压在原文上。
4. Word/TXT 走另一条路：把识别框按 y 坐标归行、行内按 x 排序，中文之间不插空格、英文之间补空格。

## 限制（都是实话）

- **表格会散**：没有版面分析，一个表格会被拆成一堆文字行，转 Excel 做不到。
- **竖排、手写、艺术字、盖章** 基本认不出。
- **docx 只有文字没有排版**：字号和分页做了还原（标题比正文大、每页一个分页符），但缩进、分栏、表格、加粗斜体都不会还原，就是一段段文字。想要「和原件长得一样」用 `_ocr.pdf`，想要「能改」用 docx，两个都留着最稳。
- 识别错字是常态，重要文件（合同、金额、身份证号）必须对着原图校对。
- 一次几十页建议分两批跑，中途挂了不用从头来（按文件独立处理，已完成的文件不会重做）。

## 和手机 App 配合

1. 手机上用 `scanner-pwa` 扫完 → 导出 PDF（系统分享，存到「文件」或发微信/网盘）。
2. 传到电脑。
3. `python ocr.py 那个.pdf`。
